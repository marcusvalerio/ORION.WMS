4. Avaliação

O que está bom

  • OKA diferença visual em relação às Novidades é clara (holofote claro × janela escura, rota × barrinhas, frases de fim diferentes).
  • OKOs perfis batem com ROLES em src/lib/permissions.ts: admin, supervisor, operator, auditor.
  • OK“Não aparece no meio de uma tarefa” pode usar a função emTarefaEmAndamento(), que já existe em src/lib/novidades.ts.
  • OKTrês passos para o operador é o tamanho certo para quem aprende no coletor.

Decisões em aberto (resolver antes do visual)

  • DecidirQuem é “novo”. Hoje só existe wms.release_notes_seen. Sugestão: tabela wms.onboarding_seen e, ao concluir o tour, marcar a versão atual de Novidades como vista. No modo demonstração, um cookie, como o NOVIDADES_COOKIE.
  • DecidirPrioridade entre as janelas. layout.tsx sempre monta <Novidades>. Enquanto o onboarding estiver pendente, as Novidades não podem abrir sozinhas.
  • Decidir“Rastreabilidade” do auditor. Não há rota própria (existem auditoria e relatorios). Para onde o passo aponta?

Riscos

  • RiscoAlvo do holofote ausente (menu recolhido, celular, sem permissão). O passo deve virar balão centralizado ou ser pulado. Para ver isso no protótipo, marque “Comex desativado”.
  • RiscoSupervisor e admin não têm as mesmas permissões. Monte os passos filtrando com can(role, …) e pelos módulos ativos da empresa.
  • Risco“Como funciona o ORION” ainda não existe. O último passo aponta para ela, então ela precisa sair junto (no menu do usuário ou em /sobre).
  • RiscoPasso do ATLAS: usar o vínculo da empresa, não o atlasUserId do usuário.

Para a implementação

  1. Atributos data-tour="…" estáveis nos alvos reais.
  2. Montar os passos a partir de perfil, permissões, módulos e ATLAS (função pura e testável).
  3. Persistência + supressão das Novidades + bloqueio em tela de tarefa.
  4. Acessibilidade: foco preso no balão, Esc = pular, setas navegam, prefers-reduced-motion.
  5. Testes no padrão de tests/identidade.test.ts.
  6. Entrada para rever o tour em “Como funciona o ORION”.
